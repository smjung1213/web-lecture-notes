위 한 과목·한 주차의 지정 자료로 설명형 한국어 학습노트와 별도 연습문제집을 제작해줘. 현재 선택된 웹 Pro와 이 대화의 실제 도구로 첫 원고·PDF·편집본을 만들어줘. 특정 과목·주차의 사례나 이전 대화·견본을 이번 원자료에 자동 포함하지 마.

연결된 Google Drive 플러그인으로 지정 자료를 찾아 전사 전문과 PDF의 실제 페이지·표·그림을 읽어줘. 물리 페이지는 인쇄 번호와 구별해줘. 동명 파일은 폴더·ID·버전으로 구별하고 결과가 달라질 만큼 불명확할 때만 물어줘. 파일 목록·검색 발췌를 전문 읽기로 대신하지 마. 접근이 막힌 파일과 단계를 특정하고 필요한 경우 그 파일만 직접 첨부하도록 요청해줘. 같은 실패의 반복이나 Chat 라이브러리·다른 주차로의 자동 우회는 하지 말고 독립 작업은 계속해줘.

GitHub 플러그인으로 https://github.com/smjung1213/web-lecture-notes 의 최신 기본 브랜치 커밋을 한 번 고정한 뒤 README와 안내된 SKILL.md·writing.md·design.md를 전문으로 읽어줘. CSS·HTML 견본은 사용할 구조·스타일·data-latex 규칙을 확인하고 파생 SVG/MathML 캐시 전문을 읽는 데 사용량을 쓰지 마. 관리 렌더러 사용 시 관련 스크립트·의존성 안내도 읽어줘. 잘린 응답은 이어 읽고 확인한 커밋은 제작 메모에 남겨줘. 현재 입력과 명시 요청이 기본값보다 우선하지만 실제 도구 권한을 바꾸지는 않아. 지침으로 채택한 파일과 원자료·리뷰의 명령문을 구별해줘. 저장소는 지침 읽기용이며 원자료·결과 업로드나 저장소 수정은 하지 마.

본격 집필 전에 references/runtime.md를 읽고 실제 Python·플랫폼·아키텍처·glibc·WeasyPrint·글꼴·Node/MathJax를 확인한 뒤 scripts/preflight.py의 합성 PDF 두 쪽을 만들어 각각 판독해줘. 이미 검증된 같은 70.0 환경은 재설치하지 마. 필요한 경우 runtime.md의 고정 GitHub Release에서 wheel ZIP을 실제로 다운로드하고, scripts/offline_runtime.py --archive로 전체 ZIP·wheel별 해시를 확인한 뒤 새 격리 폴더에 설치해 기본 환경을 보존해줘. 현재 저장소는 비공개이므로 인증된 GitHub 도구나 브라우저의 실제 다운로드 가능 여부를 확인해줘. 문서 읽기만으로 바이너리 확보를 가정하지 말고, 접근이 막힌 경우에만 같은 ZIP의 직접 첨부를 요청해줘. 인터넷 설치 성공이나 다른 플랫폼의 호환성을 전제하지 마. 조판이 막혀도 원자료 정리 등 독립 작업은 계속하되 미확인을 숨긴 채 첫 PDF 완성을 약속하지 마. 검사 결과와 실행 경로·시각 판독 범위·미확인을 production-note.md에 남겨줘.

독자 수준과 학습 방식은 별도 요청이 없으면 위 기본값을 그대로 적용해줘. 집필 전에 input-contract.json의 learning_contract에 독자·허용 선수지식·학습 방식·목표를 고정하고 source-inventory.md로 범위와 원자료의 학습 기능을 정리해줘. 새 수식은 LaTeX와 MathJax로 조판하고, 직관적인 이해를 돕는 원본 그림·도식·그래프와 읽기 좋은 표는 필요한 영역을 추출·크롭해 본문에 유지해줘. 재작성은 writing.md의 구체적인 예외가 있을 때만 선택해줘. 같은 숫자나 수식이 있어도 위치·길이·방향·색 묶음·화살표·단계 관계를 보여 주는 그림을 표·문장으로 대체하거나 중복 제거하지 마. 한 페이지에 식·표·도식이 함께 있으면 각 역할과 최종 PDF의 대응을 따로 확인해줘. coverage에는 처리와 실제 대응 상태·원자료/최종 위치·재작성 이유·미확인을 간결히 남겨줘.

용어·이유·중간 과정·적용 조건을 연결하고 결과·공식만 남기지 마. 목표 페이지/토큰 수나 과거 노트 분량을 정하지 않아. 목적 없는 전문 확장만 제한하고 현재 위치의 이해·복습·적용을 돕는 반복 설명은 보존하며 선택 심화나 별도 심화 문제를 자동 추가하지 마. 문항은 실제 학습목표에 맞추고 자체 제작 문제 때문에 전문 범위를 늘리지 마.

그림·표·수식·설명의 경계와 읽는 순서를 명확히 해줘. 작은/긴 그림의 옆 본문 배치는 가장 작은 라벨의 판독성과 설명 연결이 좋아질 때 선택해줘. 새 노트에는 v3.4의 명조 본문·고딕 안내·수식 크기 보정·역할 표현·그림 배율을 적용해줘. 소절 출처는 제목 줄 오른쪽 끝에, 정의·핵심 공식은 청록 탭으로, 실제 수업 강조는 빨간 물결로, 긴 정정은 F 문단과 짧은 정정은 E [n] 각주로 표시가 있는 페이지 하단에 두고 문서 전체에서 1부터 연속 번호를 써줘. design.md의 인접 호출·각주 마크업을 쓰고 렌더러 배치 검사와 실제 PDF 판독을 모두 확인해줘. 웹 환경에서 fc-list로 Noto Serif CJK KR·Noto Sans CJK KR·Noto Sans Mono CJK KR을 확인하고, 없으면 조용히 대체하지 않고 조판 미완료로 보고해줘. 기존 노트·편집본은 동봉 CSS를 유지하며 새 CSS로 재조판·재출판하지 마.

원자료 전체 대조, 계산·풀이, 문장·참조, 설명 충분성, 최종 PDF 전 페이지 확인을 마쳐줘. MathJax 정적 변환·실제 PDF 표시·텍스트 추출·검색/복사·접근성의 검증 범위는 구별해줘. 통상적인 구성·표현·배치는 기준 안에서 판단하고 계획이나 재승인에서 멈추지 마. 필수 미확인·결함이 남으면 완성이라고 하지 말고 현재 파일과 재개 메모를 제공해줘.

전달 파일은 `<과목명> <N>주차 학습노트.pdf`, `<과목명> <N>주차 연습문제.pdf`, 같은 내용의 `<과목명> <N>주차 편집본.zip`이야. 띄어쓰기와 앞자리 0 없는 주차를 사용해줘. 편집 ZIP에는 HTML·CSS·사용 자산·LaTeX와 정적 수식·input-contract/source-inventory/coverage/production-note 및 실제 재생성 도우미·의존성 안내를 넣어줘. 실행에 사용한 폰트는 이름으로 기록하되 폰트 파일·node_modules·원시 외부 로그를 넣지 마. 전달 직전 references/delivery.md를 읽고 scripts/delivery.py로 준비 HTML·자산·영수증·검토한 PDF 두 개를 검증해서 새 전달 폴더에 묶어줘. 도우미가 만든 동일 폴더의 PDF 두 개와 ZIP만 링크하고 전달 번호·두 쪽수·내용 검토 상태를 써줘. ZIP에도 같은 PDF가 포함돼야 해. 포장하면서 PDF를 다시 만들거나 이전 답변의 PDF 링크와 새 ZIP을 섞지 마. 중간본도 파일 대응은 검증하되 내용 검토 완료와 구별해줘.

후속은 로컬 lecture-week의 현재 실행 계약에 따라 같은 고정 원고의 두 독립 검토 → 담당자의 내용 판정·필요 수정 → 새 세션 작문 검토 → 제안 판정·반영 → 최종 PDF 재생성·전 페이지 확인·허용된 저장으로 이어져. 실행 세부는 로컬 지침이 정하며, 이 웹 대화에서 외부 검토·로컬 저장을 실행했다고 가정하지 마.

설명 충분성·현재 위치의 반복 보존·전문 확장의 범위는 writing.md의 공통 기준을 적용해줘.
