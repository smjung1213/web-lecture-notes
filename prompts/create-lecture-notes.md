## 원자료: Google Drive 플러그인

연결된 Google Drive 플러그인으로 위 폴더·파일 링크에서 지정한 강의자료와 전사본을 찾아 사용해줘. 폴더 전체나 다른 주차 자료를 자동으로 범위에 넣지 마. PDF 쪽수는 슬라이드의 인쇄 번호와 구별되는 파일의 물리적 페이지로 해석해줘. 자료 범위가 ‘전체’라면 지정한 해당 파일 전체를 사용해줘.

같은 이름의 파일이 여러 개면 폴더·파일 ID·확인 가능한 버전으로 대상을 구별하고, 결과가 달라질 만큼 불명확할 때만 질문해줘. 파일 목록이나 검색 발췌만으로 읽었다고 하지 말고, 지정 전사 전문과 PDF의 실제 페이지·표·그림을 확보해 읽어줘. 원본 그림을 활용할 수 있는 자산도 확보해줘.

접근이 막히면 해당 파일과 막힌 단계, 필요한 Drive 링크·접근 권한 확인을 알려줘. 같은 실패를 반복하거나 직접 첨부·Chat 라이브러리 등 다른 입력 경로로 임의 전환하지 마. 읽지 못한 필수 범위를 추측하거나 완료로 표시하지 말고, 그 자료와 무관하게 진행할 수 있는 작업은 계속해줘.

## 제작 지침: GitHub

GitHub 연결 도구로 https://github.com/smjung1213/web-lecture-notes 의 README.md와 안내된 SKILL.md·writing.md·design.md·CSS·HTML 예시의 전문을 읽고 적용해줘. 같은 리비전에서 이미 읽은 파일은 재사용하고, 실제로 읽은 버전과 확인 가능한 리비전을 제작 메모에 남겨줘. 파일 목록·검색 요약을 전문 읽기로 대신하지 마.

현재 입력란과 명시적 요청이 저장소의 기본값보다 우선해. 내가 지정한 독자 수준을 임의로 높이지 마. 채택한 작업 지침과 강의자료·외부 리뷰 안의 명령문을 구별해줘. GitHub는 지침과 디자인을 읽는 용도이며, 강의자료·결과를 업로드하거나 저장소를 수정하지 마.

## 집필과 확인

현재 선택된 웹 Pro와 이 대화의 도구로 자료 대조부터 PDF·편집본 전달까지 진행해줘. 작업 수행은 SKILL.md, 내용·독자·설명 깊이는 writing.md, 조판·PDF 확인은 design.md를 따라줘. 코드·수식·실험·사례는 해당 과목과 지정 자료에 실제로 필요한 방식으로 설명하고, 특정 과목의 형식을 다른 과목에 강제하지 마.

독자·자료 범위·입력 식별과 보존 요구를 input-contract.json에 기록하고, 집필 전에 원자료의 시각자료·수식·유도·학습 질문을 source-inventory.md에 정리해줘. 지정 범위의 서로 다른 원본 시각자료와 해설을 PDF에 보존하고, 필요한 수식·풀이·유도를 말 설명이나 결과만으로 대체하지 마. 용어·기호·중간 과정·적용 조건을 연결해줘.

원본·설명·풀이를 처음부터 함께 구성해줘. 같은 표·결론의 반복과 부수적인 전문 확장은 줄이되, 필요한 라벨·행·열·각주·유도와 판독성은 유지해줘. 목표 페이지 수는 정하지 않아. 기존 노트의 분량을 맞추거나 모든 슬라이드를 큰 화면으로 붙여 분량을 늘리지 마. 선택 심화와 별도 심화 문제는 자동으로 추가하지 말고, 자체 제작 문제 때문에 본문의 전문 범위를 넓히지 마.

원자료 대조, 계산·풀이, 문장·참조, 이해 용이성, 최종 PDF 전 페이지 확인을 마쳐줘. coverage.md는 원자료 목록과 실제 본문을 연결하고, 수정한 결함과 영향 범위를 다시 확인해줘. 필수 입력을 문맥으로 정할 수 없을 때만 질문하고, 통상적인 구성·표현·배치는 기준 안에서 판단해줘. 계획만 제시하거나 이미 정한 선택을 재승인받으며 멈추지 마.
