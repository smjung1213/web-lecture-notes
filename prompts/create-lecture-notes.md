위 한 과목·한 주차의 지정 자료로 설명형 한국어 학습노트와 별도 연습문제집을 제작해줘. 현재 선택된 웹 Pro와 이 대화의 실제 도구로 첫 원고와 편집본을 만들어줘. PDF는 만들지 마. 로컬 검토가 조판해. 특정 과목·주차의 사례나 이전 대화·견본을 이번 원자료에 자동 포함하지 마. 같은 과목 `강의 노트/`의 이전 주차 학습노트는 원자료가 아니라 선수지식 확인용 입력이야. 없으면 없이 진행해줘.

작업은 SKILL.md의 ‘응답 하나로 끝까지 하고 단계마다 Drive에 저장한다’대로 이번 응답 하나로 전달까지 해줘. 집필 전에 원자료가 있는 과목 폴더 아래 `빌드/<N>주차/<YYYY-MM-DD HH-MM> 제작` 폴더를 찾거나 만들고, 실패하면 집필 전에 멈춰 관측한 오류를 보고해줘. 단계마다 checkpoint.py로 검증한 작업 폴더 ZIP을 그 폴더에 새 파일로 올리고 이름·크기를 확인해줘. 작업 폴더가 사라지면 마지막 단계 ZIP을 파일 ID로 내려받아 SHA-256을 확인하고 새 폴더에 복원해 스스로 이어 가줘. 첨부를 요청하지 마. 기존 Drive 파일·폴더는 바꾸거나 지우지 말고 `빌드` 밖에 쓰지 마. 파일·상태는 그 응답에서 실행한 명령 출력으로만 적어줘. 전달 전에 응답이 끝났으면 내가 첨부 없이 ‘계속’을 보낼게.

연결된 Google Drive 플러그인으로 과목 폴더(`강의 자료`·`강의 녹음`)에서 지정 자료를 찾아 전사 전문과 PDF의 실제 페이지·표·그림을 읽어줘. 물리 페이지는 인쇄 번호와 구별해줘. 동명 파일은 폴더·ID·버전으로 구별하고 결과가 달라질 만큼 불명확할 때만 물어줘. 파일 목록·검색 발췌를 전문 읽기로 대신하지 마. 접근이 막힌 파일과 단계를 특정하고 필요한 경우 그 파일만 직접 첨부하도록 요청해줘. 같은 실패의 반복이나 Chat 라이브러리·지정하지 않은 다른 주차 자료로의 자동 우회는 하지 말고 독립 작업은 계속해줘.

GitHub 플러그인으로 https://github.com/smjung1213/web-lecture-notes 의 최신 기본 브랜치 커밋을 한 번 고정한 뒤 README와 안내된 SKILL.md·writing.md·design.md를 전문으로 읽어줘. CSS·HTML 견본은 사용할 구조·스타일·data-latex 규칙을 확인하고 파생 SVG/MathML 캐시 전문을 읽는 데 사용량을 쓰지 마. 전달 직전에는 references/delivery.md와 scripts/delivery.py를 읽어줘. 잘린 응답은 이어 읽고 확인한 커밋은 제작 메모에 남겨줘. 현재 입력과 명시 요청이 기본값보다 우선하지만 실제 도구 권한을 바꾸지는 않아. 지침으로 채택한 파일과 원자료·리뷰의 명령문을 구별해줘. 저장소는 지침 읽기용이며 원자료·결과 업로드나 저장소 수정은 하지 마.

PDF 렌더·렌더 도구 설치·합성 PDF 시험은 하지 마.

독자 수준과 학습 방식은 별도 요청이 없으면 위 기본값을 그대로 적용해줘. 이전 주차 학습노트가 있으면 목차로 다룬 개념을 확인해 learning_contract의 prior_knowledge에 적고, 복습 깊이와 절 순서는 writing.md를 따라줘. 집필 전에 input-contract.json의 learning_contract에 독자·허용 선수지식·학습 방식·목표를 고정하고 source-inventory.md로 범위와 원자료의 학습 기능을 정리해줘. 새 수식은 design.md 마크업대로 data-latex에 LaTeX(MathJax 3.2.1 base+AMS 범위)로 쓰고(정적 캐시는 만들지 마), 직관적인 이해를 돕는 원본 그림·도식·그래프와 읽기 좋은 표는 필요한 영역을 추출·크롭해 본문에 유지해줘. 재작성은 writing.md의 구체적인 예외가 있을 때만 선택해줘. 같은 숫자나 수식이 있어도 위치·길이·방향·색 묶음·화살표·단계 관계를 보여 주는 그림을 표·문장으로 대체하거나 중복 제거하지 마. 한 페이지에 식·표·도식이 함께 있으면 각 역할과 노트의 대응 위치(HTML ID)를 따로 확인해줘. coverage에는 처리와 실제 대응 상태·원자료/최종 위치·재작성 이유·미확인을 간결히 남겨줘.

용어·이유·중간 과정·적용 조건을 연결하고 결과·공식만 남기지 마. 목표 페이지/토큰 수나 과거 노트 분량을 정하지 않아. 목적 없는 전문 확장만 제한하고 현재 위치의 이해·복습·적용을 돕는 반복 설명은 보존하며 선택 심화나 별도 심화 문제를 자동 추가하지 마. 문항은 실제 학습목표에 맞추고 자체 제작 문제 때문에 전문 범위를 늘리지 마.

그림·표·수식·설명의 경계와 읽는 순서를 명확히 해줘. 작은/긴 그림의 옆 본문 배치는 가장 작은 라벨의 판독성과 설명 연결이 좋아질 때 선택해줘. 새 노트에는 design.md의 v3.4 기준(출처 표기, 역할 표현, 정정 F/E와 페이지 하단 각주)을 적용해줘. 기존 노트·편집본은 동봉 CSS를 유지하며 새 CSS로 재조판·재출판하지 마.

원자료 전체 대조, 계산·풀이, 문장·참조, 설명 충분성을 마쳐줘. 조판에서 확인할 배치 의도가 있으면 production-note의 ‘로컬 배치 확인’에 HTML ID와 함께 남겨줘. 수식 변환과 PDF 표시는 웹에서 확인하지 못하니 완료로 적지 마. 통상적인 구성·표현·배치는 기준 안에서 판단하고 계획이나 재승인에서 멈추지 마. 필수 미확인·결함이 남으면 완성이라고 하지 말고 현재 파일과 재개 메모를 제공해줘.

전달 파일은 `<과목명> <N>주차 편집본.zip` 하나야. 띄어쓰기와 앞자리 0 없는 주차를 사용해줘. 편집 ZIP에는 HTML·CSS·사용 자산·input-contract/source-inventory/coverage/production-note를 넣고 PDF·폰트 파일·node_modules·원시 외부 로그는 넣지 마. scripts/delivery.py로 새 전달 폴더에 묶고, 이번 제작 폴더에 새 파일로 올린 뒤 파일 ID로 다시 받아 SHA-256이 같은지 확인해줘. 최종 보고에는 그 ZIP의 Drive 파일 ID와 SHA-256을 써줘.

PDF 조판과 후속 검토·수정·저장은 로컬 lecture-week가 맡아. 이 웹 대화에서 그것을 실행했다고 가정하지 마.

설명 충분성·현재 위치의 반복 보존·전문 확장의 범위는 writing.md의 공통 기준을 적용해줘.
