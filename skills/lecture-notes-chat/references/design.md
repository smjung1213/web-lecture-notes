# 읽기·필기·편집을 위한 디자인

## 기본값

`assets/lecture.css`와 `assets/layout-sample.html`이 재사용 출발점이다. 견본은 합성 자료이며 강의 내용·문제·출처로 인용하지 않는다. 원본 강의 그림 대신 견본의 합성 그림을 쓰지 않는다.

- A4, 좌우 30mm, 위 22mm/아래 20mm. 본문 10.5pt·줄 간격 1.72·왼쪽 정렬. 한국어 양끝 정렬은 하지 않는다.
- Noto Sans CJK KR/Noto Sans KR 계열, 코드는 읽기 좋은 고정폭. 설치된 글꼴만 사용하고 없으면 한글을 지원하는 대체 글꼴을 확인해 보고한다. 원격 폰트를 필수로 만들지 않는다.
- 첫 페이지에 제목·범위·목표·한 열 목차를 깔끔하게 모은다. 이번 사용자는 그 뒤 본문이 시작되는 구성을 선호한다. 페이지를 맞추려고 내용·서체를 줄이지 않고 목차가 길면 자연스럽게 이어지게 한다.
- 정의·이유는 문단, 같은 기준의 비교는 표, 절차는 단계. 소제목과 선택적 강조로 복습 경로를 만든다. 모든 문장을 박스/목록으로 바꾸지 않는다.

## 출처와 정정

짧은 제목 바로 오른쪽에 작은 태그를 둔다. 페이지 끝으로 밀거나 고정 좌측 태그 열을 만들지 않는다. 일반 설명에 장식용 좌측 세로선은 없다.

| 구분 | 표시 |
|---|---|
| 교수님 추가 설명 | 일반 본문 + 민트 태그 |
| 노트 보충 풀이 / 외부 보충 / 보충 설명 | 일반 본문 + 라벤더 태그, 분류명 유지 |
| 외부 근거 미확인 / 확인 필요 | 필요한 부분만 옅은 노랑, 사실 확인 상태를 명시 |
| 심화 · 선택 읽기 | 소절 제목 옆 라벤더 태그, 외부 보충 분류 유지 |
| 응용·심화 문제 · 강의 범위 | 기본 문제 뒤 별도 구역, 강의 범위 문구 명시 |
| 자료 정정 | 옅은 분홍 전체 박스·얇은 테두리 |
| 정답 | 12pt 굵은 답 + 녹색 태그. 가로선 뒤 ‘풀이 과정’과 해설 |

정정 박스 안의 **원자료 / 정정 내용 / 근거는 작은 박스가 아니라 회색·녹색·파란색 글씨 라벨**이다. 각 항목은 별도 행에 놓고 이유는 가로선 아래에 둔다. 색이 없어도 이름으로 구별할 수 있게 한다.

짧은 정정은 통째로 유지한다. 긴 정정은 원자료+바른 핵심 설명을 붙여 두고 긴 근거/이유만 ‘근거·해설 계속’으로 나눌 수 있다. 틀린 원문만 페이지 끝에 남기지 않는다. CSS의 `.correction-core`가 함께 읽을 부분을 나타낸다. 모든 긴 블록을 무조건 분할 금지하지 않는다.

## 그림·표·코드·수식

- 작은 사진과 짧은 관련 설명은 `.figure-aside`로 나란히 배치할 수 있다. 값이 빽빽한 도표·참조표는 본문 폭을 확보한다. 병렬 배치가 판독성을 떨어뜨리면 세로로 놓는다.
- 원자료 크롭의 비율·값·축·범례·주소·화살표·주석을 보존한다. 원본 재색칠·SVG/CSS 재구성은 기본 경로가 아니다. 작은 표는 원본 부분 확대를 붙일 수 있지만 전체 참조 정보를 삭제하지 않는다.
- 같은 의미의 설명 표와 그림을 불필요하게 중복하지 않는다. 다만 원래 그림 배치가 의미를 담으면 유지하고 텍스트 전사는 검색 보조로 분리한다.
- 코드는 차콜 배경과 밝은 글씨. 토큰에 색을 주더라도 문자·공백·들여쓰기를 바꾸지 않는다. 지원하지 않는 언어는 밝은 단색이 낫다. 코드에 맞춰 글씨를 계속 줄이지 말고 의미가 같은 줄바꿈이나 가로 배치 등 읽을 수 있는 구성을 택한다.
- 간단한 지수·진법의 밑은 동일 글꼴의 보통 숫자를 `<sup>`·`<sub>`로 묶는다. `₁₀`처럼 글리프마다 대체 글꼴이 달라질 수 있는 문자 조합에 의존하지 않는다. 분수 등은 실제 수식으로 조판하고 raw LaTeX를 노출하지 않는다. 복잡한 수식의 원문은 편집 HTML에 함께 보존한다.

## 문제·풀이와 PDF 확인

문제 옆에 답을 노출하지 않는다. 각 문서 권말에 정답과 풀이를 두고 실제 `href="#..."` 목적지를 연결한다. 문제의 조건과 최소 풀이 공간은 함께 둔다. 추가 필기 공간은 길이에 따라 이어질 수 있다.

풀이 괘선은 `.guide`의 일반 `border-bottom`을 사용한다. **투명 반복 그라디언트로 만들지 않는다.** 같은 PDF가 한 렌더러에서는 정상이고 다른 뷰어에서는 검은 박스나 선 누락으로 보였기 때문이다.

PDF가 생성되면:

1. 모든 페이지의 흐름·잘림·겹침·표 머리글·문제와 풀이 공간·정정 분리를 살핀다.
2. 수식, 복잡한 도표, 코드, 풀이 공간을 확대한다. 형식이 바뀐 경우 사용자가 읽는 뷰어 또는 다른 렌더러로 대표 페이지를 확인한다. 사용할 수 없으면 미확인이라고 기록한다.
3. 목차와 문제↔정답 목적지를 확인한다. 자동 목적지 검사와 실제 앱 클릭 확인을 구별한다.
4. 보이는 수식과 추출 텍스트를 대조한다. 분수·지수의 추출 순서가 깨져도 시각적 누락으로 오판하지 않는다. HTML을 공식 검색·편집 동반 파일로 제공한다. HTML이 있다는 사실도 PDF의 검색·복사 성공을 뜻하지 않는다.
5. PDF를 만든 뒤 HTML 내용을 바꾸었다면 해당 PDF를 다시 생성한다. 이전 완성본을 덮어쓰지 말고 새 출력 폴더를 사용한다.

## 선택적 렌더링 도우미

Python 환경에 WeasyPrint가 있으면 다음처럼 쓴다. `scripts/requirements.txt`는 이 패키지를 시험한 버전이며 매번 재설치를 요구하는 계약이 아니다.

```text
python scripts/render.py /작업폴더/notes.html /새출력폴더/과목_W01_학습노트.pdf
python scripts/render.py /작업폴더/workbook.html /새출력폴더/과목_W01_연습문제.pdf
```

도우미는 입력 HTML 옆의 CSS·그림을 읽고, 누락된 참조가 있거나 출력 파일이 이미 있으면 중단한다. 외부 URL의 그림·폰트는 가져오지 않는다. 필요한 외부 그림은 사용자가 허용한 범위에서 로컬로 준비하고 출처를 보존한다. 이 도우미의 성공은 내용·시각 검토 완료가 아니다.

## 두 심화 표시와 긴 해설

선택 설명은 예를 들어 `<h3>추가 탐구 <span class="tag supplement">외부 보충 · 심화 · 선택 읽기</span></h3>`로 표시한다. 긴 제목은 자연스럽게 줄바꿈하며 글씨를 줄이지 않는다. 긴 선택 설명은 목차와 이어지는 소제목에도 선택 읽기임을 적는다. 짧으면 관련 본문 뒤, 길면 권말에 두며 대형 장식 박스나 작은 회색 글씨로 숨기지 않는다.

문제집에는 `응용·심화 문제 · 강의 범위`를 구역 제목으로 적고 기본 문제와 구별한다. 두 구역의 정답·풀이 역시 권말에서 구별하며 문제↔정답 링크를 유지한다.

긴 해설은 의미가 완결되는 지점에서 나누고 다음 페이지에 `문제 N 풀이 계속` 제목을 둔다. `.answer-continuation`을 사용할 수 있다. 실제 PDF에서 분리 지점을 확인한 뒤 적용하며, 모든 해설에 고정 페이지 나눔을 강제하지 않는다.

관리 렌더러의 기본 필수 폰트는 `Noto Sans CJK KR`이다. 다른 설치 폰트를 실제로 확인해 사용할 때 `--font '폰트 이름'`으로 명시한다. 해당 글꼴을 CSS에도 반영한다. 폰트/자산 오류나 렌더링 실패를 PDF 완료로 보고하지 않는다.
