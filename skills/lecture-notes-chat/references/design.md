# 읽기·필기·편집을 위한 디자인

## 기본값

`assets/lecture.css`와 `assets/layout-sample.html`이 재사용 출발점이다. 견본은 합성 자료이며 강의 내용·문제·출처로 인용하지 않는다. 원본 강의 그림 대신 견본의 합성 그림을 쓰지 않는다.

- A4, 좌우 30mm, 위 22mm/아래 20mm. 본문 10.5pt·줄 간격 1.72·왼쪽 정렬. 한국어 양끝 정렬은 하지 않는다.
- Noto Sans CJK KR/Noto Sans KR 계열, 코드는 읽기 좋은 고정폭. 설치된 글꼴만 사용하고 없으면 한글을 지원하는 대체 글꼴을 확인해 보고한다. 원격 폰트를 필수로 만들지 않는다.
- 첫 페이지에 제목·범위·목표·한 열 목차를 깔끔하게 모은다. 이번 사용자는 그 뒤 본문이 시작되는 구성을 선호한다. 내용의 선택·깊이는 writing.md로 정하고, 페이지를 맞추려고 필요한 이유·조건·풀이 또는 글자 크기를 줄이지 않는다. 목차가 길면 자연스럽게 이어지게 한다.
- 정의·이유는 문단, 같은 기준의 비교는 표, 절차는 단계. 소제목과 선택적 강조로 복습 경로를 만든다. 모든 문장을 박스/목록으로 바꾸지 않는다.

## 탐색·배치의 공통 규칙

- 표지·PDF 제목에는 표시 과목명과 ‘N주차 학습노트/연습문제’를 사용한다. 주제명은 부제로 둘 수 있다. 목차는 주요 절·학습에 필요한 소절과 PDF 쪽수·링크를 제공한다. 머리글에는 과목·주차와 현재 장을 표시한다.
- 독자용 범례를 한 번 둔다. 출처(교수 설명/노트 풀이/외부 자료)와 상태(정정/미확인)는 다른 정보다. 같은 색이라는 이유로 출처를 합치거나 미확인 표시를 없애지 않는다.
- 장·확인 문제·문제별 해설을 무조건 새 쪽에서 시작하지 않는다. 문제집의 풀이 공간처럼 목적이 있는 여백은 유지하고, 큰 공백은 내용 연결·그림 크기·필기 목적을 보고 판단한다. 빈 면적 비율은 후보 탐지용이며 자동 불합격 기준이 아니다.
- 공통 `lecture.css`는 그대로 복사하고 주차 특화 변경은 `local.css`에 둔다. 공통 CSS 변경은 견본과 관찰된 실제 결함에서 확인한 뒤 배포한다. 이전 편집본에 새 CSS만 덮어쓰고 검토 완료로 처리하지 않는다.
- 짧은 판정·단위·값 열에는 `.short-cell` 또는 `.nowrap`과 적절한 열 폭을 사용한다. 긴 설명 열은 줄바꿈을 허용한다. 표 전체에 nowrap을 적용하여 넘침을 만들지 않는다.
- 윗첨자·아래첨자는 기본 CSS의 `vertical-align` 방식으로 조판한다. 시각 표시, 추출 순서, 실제 앱의 검색·복사는 따로 확인한다. 일반 텍스트 복사에서 `2¹⁰`이 `210`으로 바뀔 수 있으므로 지수가 제자리에 추출되는 것과 `2^10` 검색·수식 의미 보존을 구별한다. 투명 문자 삽입으로 추출 결과를 억지로 맞추지 않는다.

## 출처와 정정

짧은 제목 바로 오른쪽에 작은 태그를 둔다. 페이지 끝으로 밀거나 고정 좌측 태그 열을 만들지 않는다. 일반 설명에 장식용 좌측 세로선은 없다.

| 구분 | 표시 |
|---|---|
| 교수님 추가 설명 | 일반 본문 + 민트 태그 |
| 노트 보충 풀이 / 외부 보충 / 보충 설명 | 일반 본문 + 라벤더 태그, 분류명 유지 |
| 외부 근거 미확인 / 확인 필요 | 필요한 부분만 옅은 노랑, 사실 확인 상태를 명시 |
| 심화 · 선택 읽기 | 필요하여 수록할 때 소절 제목 옆 라벤더 태그. 원자료/외부 보충의 실제 출처 구분 |
| 응용·심화 문제 · 강의 범위 | 필요하여 제공할 때 기본 문제 뒤 별도 구역, 강의 범위 문구 명시 |
| 자료 정정 | 짧은 주석 기본. 대비가 필요한 박스는 옅은 분홍 배경·얇은 테두리 |
| 정답 | 12pt 굵은 답 + 녹색 태그. 가로선 뒤 ‘풀이 과정’과 해설 |

정정 박스를 사용할 때 **원자료 / 정정 내용 / 근거는 작은 박스가 아니라 회색·녹색·파란색 글씨 라벨**이다. 필요한 항목을 짧게 놓고 본문의 풀이를 반복하지 않는다. 추가로 필요한 바른 읽기 안내만 가로선 아래에 두고 편집 판단 이력은 제작 메모로 옮긴다. 색이 없어도 이름으로 구별할 수 있게 한다.

짧은 정정은 통째로 유지한다. 긴 정정은 원자료+바른 핵심 설명을 붙여 두고 긴 근거/학습 해설만 ‘근거·해설 계속’으로 나눌 수 있다. 틀린 원문만 페이지 끝에 남기지 않는다. CSS의 `.correction-core`가 함께 읽을 부분을 나타낸다. 모든 긴 블록을 무조건 분할 금지하지 않는다.

## 그림·표·코드·수식

- 작은 사진과 짧은 관련 설명은 `.figure-aside`로 나란히 배치할 수 있다. 값이 빽빽한 도표·참조표는 본문 폭을 확보한다. 병렬 배치가 판독성을 떨어뜨리면 세로로 놓는다.
- 원자료 크롭은 사용한 부분의 의미를 읽는 데 필요한 비율·값·축·범례·주소·화살표·주석을 보존한다. 원본 쪽의 경계 바깥까지 대조해 필요한 제목·라벨·테두리를 잘라내거나 인접 글자 조각을 남기지 않는다. 일부 발췌는 writing.md의 필요 기준에 따라 범위를 표시하고 전체인 것처럼 보이지 않게 한다. 큰 표의 대표값 편집과 전체 참조표의 수록 여부도 내용 기준으로 정한다. 기존 원본의 재색칠·SVG/CSS 재구성은 기본 경로가 아니며 전사에만 남은 필요한 판서의 재구성은 아래 기준을 따른다.
- 같은 의미의 설명 표와 그림을 불필요하게 중복하지 않는다. 다만 원래 그림 배치가 의미를 담으면 유지하고 텍스트 전사는 검색 보조로 분리한다.
- 코드는 차콜 배경과 밝은 글씨를 사용한다. 언어를 식별할 수 있는 예시 코드에는 **구문 강조를 기본 적용**한다. 키워드·자료형/전처리 지시문은 `.kw`, 숫자는 `.num`, 문자열은 `.str`, 주석은 `.com` 등 기본 CSS의 색상 클래스로 구별한다. 코드에 맞춰 글씨를 계속 줄이지 말고 읽을 수 있는 배치를 택한다.
- 색상은 HTML의 정적 `<span class="kw">int</span>` 같은 표시와 로컬 CSS로 적용한다. CSS에 색상 정의만 있어도 코드가 자동 분류되는 것은 아니다. 언어용 토크나이저나 직접 표시를 사용할 수 있으나 PDF 생성 전에 색상이 정적 HTML에 반영되어 있어야 하며 브라우저 JavaScript 실행에 의존하지 않는다.
- 구문 강조 전후의 코드 문자·공백·줄바꿈·들여쓰기를 보존한다. 색상 때문에 코드를 고치거나 글꼴·굵기·크기를 바꾸지 않는다. 실행 결과, 바이트 덤프, 비트 도식, 일반 텍스트에는 언어 구문 색상을 억지로 적용하지 않는다. 언어를 판단할 수 없거나 지원하지 않으면 밝은 단색을 유지한다. 원자료의 코드 이미지는 재색칠하지 않는다.
- 최종 PDF의 코드에서 구문별 색상과 주석의 명암·가독성을 확인한다. 코드가 단색이면 HTML의 토큰 표시와 CSS 적용을 확인하고, 색상 추가로 줄바꿈이나 페이지 흐름이 달라지지 않았는지 살핀다.
- 간단한 지수·진법의 밑은 동일 글꼴의 보통 숫자를 `<sup>`·`<sub>`로 묶는다. `₁₀`처럼 글리프마다 대체 글꼴이 달라질 수 있는 문자 조합에 의존하지 않는다. 분수 등은 실제 수식으로 조판하고 raw LaTeX를 노출하지 않는다. 복잡한 수식의 원문은 편집 HTML에 함께 보존한다. 순서가 맞게 추출돼도 지수와 기저 숫자가 붙을 수 있으므로, 이를 검색·접근성 전체 해결로 보고하지 않는다.

### 판서 재구성·보충 예시의 조판

- [집필 기준](writing.md#판서시각-지시가-있는-전사)에 따라 비트열·주소·수직선·화살표·수치 관계는 편집 가능한 SVG, 계산 과정은 HTML과 수식 조판을 우선한다. 손글씨 모사보다 값·관계·단계의 판독성을 우선한다.
- Imagen 등 이미지 생성은 현재 도구로 가능한 개념 삽화에만 선택적으로 쓴다. 정확한 숫자·코드·수식 도식을 이미지 생성에 맡기지 않으며 특정 도구나 외부 서비스 사용을 필수로 요구하지 않는다.
- 관련 설명 바로 옆이나 뒤에 본문 폭에 맞춰 넣고 캡션에 재구성/보충 예시와 짧은 근거 위치를 표시한다. ‘노트 보충 예시’는 기존 `.tag.supplement` 표시를 사용할 수 있다. 긴 도식은 의미 단위로 나누며 PDF에 맞추려고 글씨를 과도하게 줄이지 않는다.
- 사용한 SVG 원본은 `assets/`에 보존하고 편집 ZIP에 포함한다. 정적 로컬 자산으로 렌더링하며 JavaScript·원격 폰트에 의존하지 않는다. SVG의 제목/설명 또는 HTML 대체 텍스트를 넣고 핵심 풀이를 본문에도 남긴다.
- 최종 PDF에서 숫자·한글·기호·선·화살표·캡션의 누락, 잘림·겹침, 색상 대비와 인쇄 크기의 가독성을 확인한다. 색만으로 관계를 구분하지 않는다. 웹 미리보기나 SVG 파일만 확인하고 PDF 반영을 완료했다고 하지 않는다.

## 문제·풀이와 PDF 확인

문제 옆에 답을 노출하지 않는다. 각 문서 권말에 정답과 풀이를 두고 실제 `href="#..."` 목적지를 연결한다. 문제의 조건과 최소 풀이 공간은 함께 둔다. 추가 필기 공간은 길이에 따라 이어질 수 있다.

풀이 괘선은 `.guide`의 일반 `border-bottom`을 사용한다. **투명 반복 그라디언트로 만들지 않는다.** 같은 PDF가 한 렌더러에서는 정상이고 다른 뷰어에서는 검은 박스나 선 누락으로 보였기 때문이다.

PDF가 생성되면:

1. 학습노트·문제집의 **모든 페이지를 글자·기호를 읽을 수 있는 크기로 개별 확인**한다. 제목·소제목·본문·캡션·표·코드·수식·문항·해설의 표시와 페이지 흐름, 잘림·겹침·풀이 공간·정정 분리를 살핀다. 작은 글자를 판독할 수 없으면 해당 부분을 더 확대한다. 고정 해상도나 확대 페이지 수만으로 충분성을 판정하지 않는다. 모아보기는 전체 배치 확인용이며 전 페이지 판독을 대신하지 않는다.
2. [문장·참조 기준](writing.md)에 따라 방향·번호 참조를 실제 대상과 함께 읽는다. 표의 계산이 맞는지와 ‘위/아래 표’의 배치가 맞는지는 별개다. 형식이 바뀐 경우 사용자가 읽는 뷰어 또는 다른 렌더러로 대표 페이지를 추가 확인한다. 사용할 수 없으면 이 추가 확인의 한계를 기록하며 주 검토의 전 페이지 판독과 구별한다.
3. 목차와 문제↔정답 목적지를 확인한다. 자동 목적지 검사와 실제 앱 클릭 확인을 구별한다.
4. 보이는 수식과 추출 텍스트를 대조한다. 분수·지수의 추출 순서가 깨져도 시각적 누락으로 오판하지 않는다. HTML을 공식 검색·편집 동반 파일로 제공한다. HTML이 있다는 사실도 PDF의 검색·복사 성공을 뜻하지 않는다.
5. PDF를 만든 뒤 HTML 내용을 바꾸었다면 해당 PDF를 다시 생성한다. 이전 완성본을 덮어쓰지 말고 새 출력 폴더를 사용한다.

수정 뒤에는 변경·이웃 페이지와 영향을 받은 참조를 다시 읽는다. 이전에 실제 판독을 끝낸 페이지의 확인 결과는 내용·배치가 유지됨을 대조한 범위에서만 이어 쓸 수 있다. 페이지 이동·줄바꿈·표 분할 등 재조판이 영향을 준 페이지도 판독하고, 영향 범위를 확정할 수 없으면 전체를 다시 확인한다. 처음부터 읽지 않은 페이지를 변경되지 않았다는 이유로 완료 처리하지 않는다.

기존 제작/검토 메모에 대상 PDF 버전, 실제 판독한 페이지 범위, 모아보기만 한 범위와 미확인 범위를 구별해 적는다. 생성·추출·자동 링크 검사 통과를 시각 검토 통과로 보고하지 않는다.

## 선택적 렌더링 도우미

Python 환경에 WeasyPrint가 있으면 다음처럼 쓴다. `scripts/requirements.txt`는 이 패키지를 시험한 버전이며 매번 재설치를 요구하는 계약이 아니다.

```text
python scripts/render.py /작업폴더/notes.html '/새출력폴더/과목명 1주차 학습노트.pdf'
python scripts/render.py /작업폴더/workbook.html '/새출력폴더/과목명 1주차 연습문제.pdf'
```

도우미는 입력 HTML 옆의 CSS·그림을 읽고, 누락된 참조가 있거나 출력 파일이 이미 있으면 중단한다. 외부 URL의 그림·폰트는 가져오지 않는다. 필요한 외부 그림은 사용자가 허용한 범위에서 로컬로 준비하고 출처를 보존한다. 이 도우미의 성공은 내용·시각 검토 완료가 아니다.

## 두 심화 표시와 긴 해설

선택 설명은 writing.md의 기준상 필요한 경우에만 수록한다. 외부 내용이면 예를 들어 `<h3>추가 탐구 <span class="tag supplement">외부 보충 · 심화 · 선택 읽기</span></h3>`로 표시하고, 원자료 내용이면 실제 출처로 표시한다. 긴 제목은 자연스럽게 줄바꿈하며 글씨를 줄이지 않는다. 필요한 긴 선택 설명에는 목차와 이어지는 소제목에도 선택 표시를 한다. 생략한 전문 내용을 전부 권말에 모으지는 않는다.

응용·심화 구역을 제공하는 경우 `응용·심화 문제 · 강의 범위`를 구역 제목으로 적고 기본 문제와 구별한다. 실제 제공한 구역의 정답·풀이를 권말에서 구별하며 문제↔정답 링크를 유지한다.

긴 해설은 의미가 완결되는 지점에서 나누고 다음 페이지에 `문제 N 풀이 계속` 제목을 둔다. `.answer-continuation`을 사용할 수 있다. 실제 PDF에서 분리 지점을 확인한 뒤 적용하며, 모든 해설에 고정 페이지 나눔을 강제하지 않는다.

관리 렌더러의 기본 필수 폰트는 `Noto Sans CJK KR`이다. 다른 설치 폰트를 실제로 확인해 사용할 때 `--font '폰트 이름'`으로 명시한다. 해당 글꼴을 CSS에도 반영한다. 폰트/자산 오류나 렌더링 실패를 PDF 완료로 보고하지 않는다.
